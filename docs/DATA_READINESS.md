## `sdci_data` 是否需要

需要，但兩個 SQLite 的角色不同：

- `ua1008l.sqlite` 是第一版必要資料。它已有實際過港、靠泊、離泊、GT、泊位與港口入口，
  比附件預期的「只靠預報快照等待欄位回填」更適合直接校準。
- `sdci.sqlite` 不是第一版最佳化的必要條件。它有 635,124 列，但其本質是 278 次輪詢造成
  的重複快照；觀測期只有 2026-07-06 至 2026-07-12。它適合第二階段建立 ETA 修訂、
  snapshot union、到港 forecast adapter，不應把列數當作 63 萬個獨立船次。
- 原始 HTML 只用於 parser 追溯與稽核，不直接進模型或 Git。

## 對附件原判定的更新

1. 「TPNet 實際內容未見過」已過期：本工作區已有可解析資料庫與原始 HTML。
2. 「時間格式未知」已解決：scraper 已把民國年正規化為 ISO 8601。
3. 「LEAVE_DT 可能拿不到」對 `ua1008l.sqlite` 已大幅緩解：進港完整時間鏈為 90.18%。
4. 「泊位座標需從零補製」需改寫：前端已有 72 個官方 marker feed 衍生座標與 OSM 幾何，
   但覆蓋不完整，仍需補製與驗證。
5. 「系統餘裕約 21%」不能直接當模型硬閾值。設計年產能與三年平均吞吐的差額不是可即時
   調度的均質備援，還受 terminal、船型、設備、堆場與尖峰分布限制；應把膝點當待估輸出。
