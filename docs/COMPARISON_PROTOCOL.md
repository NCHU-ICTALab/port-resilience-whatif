# 與港口現況的比較與驗證規約

## 可否確定港口端戰時排程比我們差？

目前不能。

公開資料只足以證明：

1. 高雄港承平時不是純 FCFS。VTS 依引水申請時間、拖船最大可用量、潮汐、船種優先、
   大型船間隔、單向航道與現場安全彈性調整進出港次序。
2. 台灣有交通／水運動員、徵用與封鎖下航運管制的法定任務。
3. 公開來源尚未提供高雄港戰時商軍共用泊位重分配演算法、完整 SOP、資源 snapshot、
   候選排程或績效資料。

第三點是「無公開證據」，不是「港方沒有能力」。因此不得用 NSGA-II 對上刻意簡化的 FCFS，
再把差距寫成「比港方改善 X%」。

## 公平的四層比較

| 層級 | 方法 | 回答的問題 |
|---|---|---|
| B0 | FCFS | 最弱、可重現的 sanity baseline |
| B1 | 公開優先權規則 | 船種／潮汐／大型船／資源優先規則有多少價值 |
| B2 | 官方規則仿真 | rolling rounds、拖船上限、單向航道、現場延誤與再排程 |
| O | NSGA-II Pareto | 在相同資訊與硬限制下，多目標候選比規則仿真改善多少 |
| X | CP-SAT 縮小實例 | NSGA-II 距可證精確解多遠 |

若之後取得港方匿名排程，另加 H（historical replay），但 H 仍不是完美 ground truth：
歷史人員面對的是當時資訊，模型若偷看未來 service time 會造成 look-ahead bias。

## 配對實驗

每個方法必須共享完全相同的：

- 船舶到港與可用資訊時點；
- 泊位相容性、徵用、受損與修復曲線；
- 引水、拖船、航道、時窗與護航批次限制；
- 隨機種子與 service-time 抽樣；
- 72 小時 horizon 與 warm-up／cool-down；
- 跨港容量上限（多港階段）。

至少回報：

- Pareto hypervolume、非支配候選數；
- 吞吐船次（若無 TEU，不冒稱貨櫃吞吐量）；
- 平均／P90 等待、makespan、優先排程偏離；
- safety／constraint violations；
- paired bootstrap 95% CI、逐情境勝平負；
- CP-SAT optimality gap（縮小實例）。

## 可用的對外措辭

通過上述實驗前：

> 本系統建立公開規則與資料上的戰時商船重分配 what-if 工具。

通過 B2 配對實驗後：

> 在所列 72 小時合成衝擊與相同硬限制下，最佳化候選相較公開規則仿真改善 X；
> 結果不代表實際港方戰時績效。

只有取得港方共同定義的資料、規則、情境與驗收後，才可討論「優於現行作業」。

## 現實性防線

- 不把「設計產能 − 年平均吞吐」直接視為 21% 即時餘裕。
- 不以 GT 代替 TEU 或貨物價值；若使用 proxy，KPI 名稱必須寫清楚。
- 不假設所有泊位同質；至少限制長度、水深、terminal／用途與徵用狀態。
- 不假設港間分流免費；要有接收港容量、航程、腹地與退回規則。
- 不把未知軍事需求最佳化；軍事優先排程是使用者輸入且不可被商船目標覆寫。
- 不發布精確攻擊、目標選擇或設備級毀損模擬。
